Every station under the sun.

ShoutKit is a native internet radio app for iPhone, iPad, Apple Watch, Apple TV and CarPlay. Thousands of live stations, a Liquid Glass player that shows the track that's playing right now, and Siri to start it — no ads, no accounts, no tracking, no API keys. Free and open source, forever.

What it does

Built the way an Apple app should be.

Pure SwiftUI, Swift 6, and the system frameworks — not a web view in a jacket. Everything below ships in the app today.

The player

Now Playing

A Liquid Glass player

A mini-player docked above the tab bar follows you everywhere, and expands into a full-screen Now Playing surface with live ICY track metadata.

Artwork

Album art, resolved live

Now Playing looks up artwork for the track on air and links straight to the matching song in Apple Music. On by default; one Settings toggle turns it off.

Sound

Equalizer & sleep timer

Preset EQ curves to colour the sound how you like it, and a sleep timer that pauses rather than stops — so resuming in the morning is one tap.

The directory

Discovery

Keyless, from first launch

Real stations out of the box via the Radio-Browser community directory — search, genres and popular stations, with no API key to register for.

Offline

Stations without the wait

Discovery results are cached on device, so a launch paints stations immediately instead of a spinner — and keeps showing them when the network drops.

Library

Favorites & recents

Backed by SwiftData and stored locally. Drag favorites into any order you like; recents remember where you left off.

Everywhere you listen

Siri · Shortcuts · Spotlight

“Play KEXP on ShoutKit”

App Intents start playback in the background without foregrounding the app, and your favorites and recents are indexed in Spotlight.

Lock Screen

Controls where you expect them

Full remote controls and now-playing info on the Lock Screen and in Control Center, plus a Dynamic Island Live Activity.

CarPlay

Favorites on the dashboard

Your favorites and recent stations on the car's screen, driven by the same playback engine as the phone — so what's playing stays in sync.

Apple Watch

A real watch app

Native now-playing and recent stations on the wrist, with a one-tap “Play Last” complication that starts your last station from the watch face.

Apple TV

Radio on the big screen

Recent and popular station shelves built for the Siri Remote, with the current track's title and artist alongside the station — the same audio engine as the iPhone app.

iPad

Not a stretched iPhone

An adaptive sidebar and multi-column station grids that hold up in full screen, Split View and Stage Manager.

Home Screen

Widgets & deep links

A widget plays a chosen favorite in one tap, and shoutkit://station?… links open the app straight to a station.

Privacy

It collects nothing. Really nothing.

Not a compromise between free and funded — there is no business model here to feed.

  • Zero data collection.

    The App Store privacy manifest declares no collected data types and no tracking domains.

  • Nothing leaves the device.

    Favorites and recents live in a local SwiftData store. There is no sync service, because there is no server.

  • Minimal network traffic.

    Public directory queries, the station streams you choose, and the anonymous play reports the community directory uses to rank popularity. That's the list.

  • This page, too.

    No fonts from a CDN, no analytics script, no cookies — one HTML file and nothing else. You can read all of it.

Free software

Yours to read, build and fork.

The app is copyleft so it stays free for everyone who gets it. The infrastructure underneath is permissive, so you can lift it into your own project.

Two licences, on purpose

  • GPL-3.0 The ShoutKit app — improvements stay free.
  • MIT The reusable packages: playback, directory, design system. Adopt them anywhere, including in closed source.

Reusable packages deliberately take no app-specific or heavyweight dependencies, so dropping one into your project doesn't drag ShoutKit along with it.

Build it in three commands

No keys, no secrets, no service to sign up for. Xcode 27 and a Mac.

git clone https://github.com/cascadiacollections/shoutkit.git
cd shoutkit
open ShoutKit.xcworkspace # then ⌘R

Prefer the terminal? swift test --disable-xctest runs the package suites on a Mac host without booting a simulator.

Standing on free software

Station data comes from Radio-Browser, a free community directory with an open API and no key requirement. ShoutKit sends a descriptive User-Agent and reports plays back so the directory's popularity ranking keeps working — the same etiquette any good client follows.

If you like the app, the directory is the part worth supporting too.

Questions

The things people ask first.

Does ShoutKit cost anything?

No. It's free software with no paywalls, no subscriptions and no in-app purchases. Every feature works whether or not you support the project.

Do I need an API key or an account?

Neither. Discovery works from first launch through the Radio-Browser community directory, which needs no key, and there's no ShoutKit account to create — your favorites and recents are stored on your device.

What data does it collect?

None. The privacy manifest declares no collected data types and no tracking. Network traffic is limited to public directory queries, the station streams you play, and the anonymous play reports the directory uses to rank popularity.

Which devices does it run on?

iPhone and iPad on iOS or iPadOS 26 and later, Apple Watch on watchOS 26 and later, and Apple TV on tvOS 26 and later — plus CarPlay, a Home Screen widget, and a watch face complication.

Can I add a station that isn't listed?

Stations come from the Radio-Browser community directory, so anything added there shows up in ShoutKit — the directory is editable by anyone. A handful of curated stations are bundled so the app is never empty.

Can I build it myself?

Yes, and it's the intended way to get it today. Clone the repository, open ShoutKit.xcworkspace in Xcode 27, and run the ShoutKit scheme — the default configuration needs no secrets.
