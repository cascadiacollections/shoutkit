# ShoutKit 0.2.0 — first TestFlight beta

**Theme:** a complete, trustworthy small app. Beta users forgive missing features; they don't
forgive broken basics or a product that feels anonymous.

**Pitch (release notes draft):**

> A free, open-source internet radio app. Zero accounts, zero tracking, zero API keys — search
> 50,000+ community-indexed stations, favorite them, and keep listening from your lock screen,
> Dynamic Island, and Siri.

## Decisions

- Bundle ID: `com.cascadiacollections.shoutkit` (+ `.Widgets` for the extension) ✅ applied
- Feature headliner: **sleep timer** ✅ shipped; home-screen quick-play widget deferred to beta 2
- Crash reporting: TestFlight built-in only — no third-party SDK (this is part of the privacy
  story, and the release notes should say so)

## Workstream A — Ship blockers

- [x] Bundle IDs migrated off `com.example.*`
- [x] `MARKETING_VERSION = 0.2.0` (app + widget targets)
- [x] `ITSAppUsesNonExemptEncryption = NO` in both Info.plists (HTTPS only)
- [x] **App icon** — programmatic placeholder (radio-wave motif on the brand gradient,
      generated via Core Graphics, single-size 1024×1024 `AppIcon.appiconset`); unblocks
      TestFlight submission today. Swap for professional design before a public release —
      see Decisions.
- [ ] App Store Connect: app record, TestFlight internal + external groups, privacy
      questionnaire (nothing collected — mirrors `PrivacyInfo.xcprivacy`), screenshots
- [ ] **Archive with the commit stamp**: build the TestFlight archive with
      `GIT_COMMIT_SHA="$(git rev-parse --short HEAD)"` so Settings → About shows the source
      revision (e.g. `0.2.0 (1) · a1b2c3d`) for screenshot-based bug repro. Without the override
      the line falls back to a clean version with no commit.

## Workstream B — Trust & feedback surfaces

- [x] Sleep timer (Now Playing bottom bar: 15/30/45/60 min presets, live countdown, cancel;
      pauses playback so morning resume is one tap)
- [x] Settings/About screen (`SettingsFeature` package, gear on Listen Now): version/build,
      in-app license texts (GPL/MIT bundled as resources), repo/issues/sponsors/Radio-Browser
      links, TestFlight feedback note, and the **play-reporting toggle** (fulfils the README
      privacy promise; gated in `AppDependencies` via `SettingsStore`)
- [x] First-run welcome overlay (`WelcomeOverlayView`, one screen, `@AppStorage`-gated):
      "Everything works without an account. Tap a station to start listening."
- [x] String Catalog adoption: a `Localizable.xcstrings` per package/target (8 total — app,
      widget, DesignSystem, RadioDirectory, and the four feature packages that needed one) plus
      manual `String(localized:)` wraps for the handful of plain-`String` APIs that don't
      auto-extract (`RadioDirectoryError.errorDescription`, `SectionHeaderView`'s literal call
      sites). Populated via `xcodebuild -exportLocalizations` / `-importLocalizations` — 92 keys
      captured across all catalogs, verified by direct inspection.

## Workstream C — Quality gate

- [ ] On-device QA checklist (~15 scenarios): backgrounding mid-stream, phone-call
      interruption, AirPods route change, Live Activity across station switches, Siri intent
      from cold launch, airplane-mode failures + Retry, Dynamic Type XXL, VoiceOver on all tabs,
      sleep timer firing while backgrounded
- [ ] Push to GitHub → CI maiden run green; tag `v0.2.0`; GitHub release mirroring TestFlight
      notes
- [ ] Apply for the **CarPlay audio entitlement** now (ships later; approval lead time is free)

## What to ask beta users

1. Streaming reliability on cellular / weak networks (buffering, stalls, recovery)
2. Battery drain during long sessions
3. Discovery quality: does search/genre browsing surface stations you actually want?
4. Lock screen / Dynamic Island behavior across station switches
5. First-30-seconds impressions from a cold install

## Exit criteria (beta 1 → beta 2)

- Crash-free ≥ 99.5% (TestFlight metrics)
- ≥ 10 external testers with structured feedback on the questions above
- No P0/P1 open for a week
- Beta 2 candidates: quick-play widget, favorites export/import, search filters

## Constraints

- iOS 26-only deployment target → beta pool needs iOS 26 devices; say so in the invite
- Built with Xcode 26 beta toolchain; TestFlight accepts beta-SDK builds during the beta season
