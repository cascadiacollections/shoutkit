# ShoutKit 0.3.0 — iOS 27 platform adoption (beta 2)

> **Closed 2026-08-07.** Every workstream below shipped. Two items did not and were moved to
> `docs/ROADMAP.md` rather than left as open boxes here: the `try?` audit (Workstream E) and
> the resizable-context / cold-launch QA (Workstream D). A closed release plan with unchecked
> boxes is how a roadmap drifts, which is exactly what happened to `docs/ROADMAP.md` over this
> release.

**Theme:** ride the iOS 27 wave while it's early. WWDC 2026 gave audio apps a purpose-built
now-playing stack and made App Intents the sole Siri surface — both land squarely on choices we
already made, so adoption is incremental rather than a rewrite.

**Context.** The active toolchain is Xcode 27 beta with the iOS 27 SDK.

> **Superseded mid-release.** This plan was written assuming the deployment target would stay at
> **iOS 26**, with every iOS 27 API behind `if #available(iOS 27, *)`. The floor was raised to
> **iOS 27** on 2026-07-15 (#109, see `DECISIONS.md`), which is why `Config/Debug.xcconfig` reads
> `27.0` and why `NowPlayingCenter` — the legacy `MPNowPlayingInfoCenter` path — no longer runs on
> any supported device. It stays in the tree as a working reference and a one-line fallback.
> Read the `#available` reasoning below as history, not as current policy. The App Store's mandatory-SDK cadence (iOS 26 SDK required since 2026-04-28)
suggests the iOS 27 SDK becomes mandatory ~spring 2027; we're ahead of it either way.

## Where WWDC26 validated existing bets (no work)

- **SiriKit deprecated, App Intents mandatory** — ShoutKit was built on App Intents from day one.
- **Scene-lifecycle required by the iOS 27 SDK** — SwiftUI `App` lifecycle already satisfies it.
- **Liquid Glass applied unconditionally in iOS 27** (compatibility flag ignored) — we designed
  for it natively on iOS 26; nothing to unwind.
- **Swift 6 strict concurrency** — already at `complete` across all packages.

## Workstream A — NowPlaying framework (headliner)

iOS 27's new `NowPlaying` framework replaces the `MPNowPlayingInfoCenter` dictionary +
`MPRemoteCommandCenter` global-singleton pattern with a typed, observable `MediaSession`. The SDK
even ships a **`RadioContent`** content type (`stationName` / `programName` /
`duration: .live`) — purpose-built for this app.

- [x] `MediaSessionNowPlayingCenter`: a second `NowPlayingPresenting` implementation in the
      Playback package — `@Observable` session state conforming to `MediaSessionRepresentable`,
      `RadioContent` for station + live track, `MediaCommand.play/pause/stop/togglePlayPause`
      mapped to the existing controller callbacks, async `Artwork` provider replacing the manual
      URLSession-and-cache dance.
- [x] Runtime selection in `PlaybackController`'s production convenience init:
      `#available(iOS 27, *)` → MediaSession path; iOS 26 → legacy `NowPlayingCenter`. The
      `NowPlayingPresenting` seam (added for testability in 0.2.0) means zero changes to the
      controller, its tests, or the fakes.
- [x] On-device verification: lock screen, Control Center, Dynamic Island transport controls,
      artwork, station switch, ad-break metadata suppression. Verified on an iPhone 17 Pro
      (iOS 27) on 2026-07-18 — no regressions vs. the legacy path.
- [x] Keep the legacy path shippable — first-beta framework; if the MediaSession path
      misbehaves in TestFlight, selection collapses back to legacy with a one-line change.
- **CarPlay note (triage outcome — since shipped):** this section deferred CarPlay out of
  0.3.0 pending the entitlement and the MediaSession prove-out. Both cleared, and CarPlay
  shipped: `ShoutKitCarPlaySceneDelegate.swift` implements the minimum scope described here,
  and `com.apple.developer.carplay-audio` is declared in `ShoutKitApp.entitlements`. The
  original triage, preserved because it turned out to be accurate about the scope:
  the current playback architecture is already viable for a
  minimal CarPlay scene. `PlaybackController` owns the app-wide play/pause/stop state and already
  exposes system-transport hooks through `NowPlayingPresenting`, while station snapshots in
  favorites/recents/App Intents carry enough metadata to populate a thin `CPListTemplate` without
  a directory refetch. The minimum scope is therefore a CarPlay scene delegate plus one station
  list template and `CPNowPlayingTemplate`, reusing the existing controller instead of introducing
  an `MPPlayableContentManager` tree. Still keep implementation out of 0.3.0: the entitlement is
  not present in the checked-in app entitlements yet, and the iOS 27 `MediaSession` path is still
  being parity-verified before it becomes the production default.

## Workstream B — App Intents 2.0 discoverability

iOS 27 Siri discovers app content through **entity schemas** contributed to Spotlight's semantic
index; apps without them are effectively invisible to the new Siri.

- [x] Adopt entity schemas for `Station` entities (favorites first) so "play ⟨station⟩" resolves
      through semantic search, not just our registered phrases. Shipped as `IndexedEntity`
      conformance + a per-launch Spotlight index push (see `DECISIONS.md`, 2026-07-12); the
      richer `AssistantSchema`/`LiveRadioStationEntity` macros wait for the deployment target to
      move to iOS 27.
- [x] Evaluate streaming intent responses ("still working…" UI) for the play intent's
      resolve-then-buffer window. Evaluated 2026-07-18 — **not adopting**:
      `PlaybackController.play` is fire-and-forget, so `perform()` returns "Playing …"
      immediately and never blocks on the buffer window, and `WarmupRadioAudioQueueIntent`
      already prewarms the socket. A streaming response would require making `perform()` await
      first-audio — worse for headless Siri playback — for no UX gain. Revisit only if the play
      intent ever awaits playback start.
- [x] Adopt the new App Intents Testing framework for the existing Siri intent (validates through
      real system pathways — fits the DI/testing culture here). Shipped as the app-hosted
      `ShoutKitTests` target (`AppIntentsPathwayTests` + `IntentSupportTests`); confirmed green via
      Cmd+U on 2026-07-18. See `DECISIONS.md`.

## Workstream C½ — SwiftUI 27 adoption

- [x] **Reorderable Favorites** — iOS 27's new list-reordering API on the Favorites tab;

## Workstream E — Swift 6.4 / concurrency idioms

- [x] `.defaultIsolation(MainActor.self)` for the six UI packages (DesignSystem + five
      feature packages); infra packages stay explicitly isolated by design.
- [x] `isolated deinit` in `NowPlayingCenter` / `AVPlayerAudioOutput`, deleting the
      `nonisolated(unsafe)` cleanup-state workarounds.
- [x] Replace the controller's state-mirroring closure hooks (`onStateChange`,
      `onNowPlayingChange`) with `Observations` async sequences owned by the Live
      Activity coordinator (with value dedup — ICY pushes repeat identical track
      info, and redundant ActivityKit updates are wasted IPC). `onStationPlayed`
      deliberately stays a closure: it's a discrete event, not observable state.
- [x] Typed throws for playback failures (`AudioStatus.failed(String)` → typed error). Shipped
      as `PlaybackError` (`.streamFailed`/`.directory`), mirroring `RadioDirectoryError`'s
      `errorDescription`/`isRetryable` shape (see `DECISIONS.md`, 2026-07-12).
- **Completed on `docs/ROADMAP.md` (#143):** the `try?` audit was unblocked by re-checking the
      gate first. On the current `xcode-27` toolchain, the `Task { try await … }` probe still
      emits no unhandled-error diagnostic, so no warning can be enabled yet; intentionally
      best-effort `try?` sites are now called out in code where the intent was ambiguous.

## Workstream D — Free wins to verify on iOS 27 (QA checklist)

- [x] `AsyncImage` now respects HTTP caching by default — confirm Radio-Browser favicon cache
      headers make `StationArtworkView`/`SpotlightCard` benefit; drop any redundant caching.
      Confirmed 2026-07-18: Radio-Browser favicons ship strong validators (`cache-control:
      max-age=31536000` + `etag`), so the shared `URLCache` caches them. Artwork already routes
      through `URLCache` via `.returnCacheDataElseLoad` in
      `ArtworkThumbnailLoader`/`ArtworkLoader` (station rows use those, not `AsyncImage`). The
      `NSCache` layer holds *decoded* thumbnails, not raw bytes — complementary to `URLCache`,
      not redundant. No changes needed.
- [x] Live Activity in the landscape Dynamic Island — verify layout. Verified on an iPhone 17
      Pro (iOS 27) on 2026-07-18 during the MediaSession now-playing pass — layout holds in
      landscape.
- **Moved to `docs/ROADMAP.md`:** resizable-iPhone-app contexts (iPhone Mirroring, iPad) —
      mini-player accessory + tab bar at arbitrary window sizes. Needs hardware, not a commit.
- **Moved to `docs/ROADMAP.md`:** the cold-launch baseline, reframed there as an ongoing
      per-build regression check rather than a one-time verification of a marketing number.

## Explicitly not doing

- **Foundation Models / Core AI / Music Understanding frameworks** — no credible ShoutKit feature
  yet; a radio app doesn't need on-device LLM inference to play streams. Revisit if a real
  feature (e.g., on-device genre tagging of unlabeled stations) earns its complexity.
- ~~**Raising the deployment target to iOS 27**~~ — done on 2026-07-15 (#109), earlier than this
  plan anticipated. Superseded; see the Context note above.

## Exit criteria

- MediaSession path verified on-device across the QA checklist; zero regressions vs. legacy
- Siri finds and plays a favorited station via semantic search on iOS 27
- Beta 1 feedback triaged; crash-free ≥ 99.5% maintained on beta 2
